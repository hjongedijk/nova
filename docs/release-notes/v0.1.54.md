# NOVA v0.1.54

The native Node-RED flow editor opens inside Settings → Connections → Node-RED, beside the existing flow overview. Opening is explicit. Active sessions renew without asking for the settings PIN again; closing the editor revokes its session and WebSocket connections. The private Node-RED admin token stays on the server. Existing reverse-proxy authentication works without NOVA's extra unlock screen.

Core flow editing, deployment, debug, context and library routes are supported. Palette installation remains in NOVA's existing Nodes controls. Native projects, login, diagnostics and arbitrary runtime endpoints are excluded. Custom nodes that need additional admin endpoints require reviewed route support. See [the editor guide](../node-red-editor.md).

This release also addresses the ARM64 gateway build failure that prevented v0.1.53's gateway image from publishing. CI checks the gateway image on both AMD64 and ARM64 before release. The pinned gateway version, provider settings, free-routing policy and persistent data remain in place.

Update NOVA and its matching gateway image together using the production Compose file. No Node-RED data migration, extra published port or flow replacement is required. Existing Node-RED flows and credentials remain authoritative.
