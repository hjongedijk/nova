# Settings inventory

Baseline: phase A, 2026-10-09. Updated phase J changes are listed at the end. This inventory describes existing behavior before the phase J settings redesign. It lists field names and ownership without reading deployment secrets. See [service and environment inventory](settings-services-inventory.md) for `.env`, Compose, OmniRoute, Node-RED, Qdrant, MQTT, Home Assistant, Proxmox, Termix, Pangolin, MCP and Windows-agent deployment settings.

## Native Windows settings and transient controls

- `mode.json` owns native `mode`, helper monitor/display, NOVA base `url`, last meaningful helper `view`, and `hotkeys` (`open,speak,mute,desktop`): `agents/windows/jarvis-agent.ps1:1183`. Compact, hidden and confirmation states do not replace the saved meaningful view.
- `GET/PUT /api/settings/helper/hotkeys` proxies native preferences; writes are guarded. Native registration warnings and paused state are reported, with an unavailable result when no compatible agent exists: `settings.controller.ts:670`; `HelperDevices.svelte:12`.
- `POST /api/settings/helper/size` accepts named `view`, `hidden`, `reducedMotion`; legacy `expanded` remains supported. This public runtime geometry control is not an administrative preference write: controller line 527; `apps/web/src/lib/api/helper.ts`.
- Native tray pause/resume is a runtime state. Audio output selection is session-local through `AudioContext.setSinkId` or a supported audio element; it is not persisted. Browser speech recognition uses the browser/Windows default input device, so the microphone test is not a physical input selector: `HelperDevices.svelte:31`.

## Public payloads and guards

`GET /api/settings` is PIN-protected when `NOVA_ADMIN_PIN` is configured and returns persona, quick actions/default indicator, sanitized skills, widgets, resolved sidebar, built-in panels, maximum pages, grouped abilities, tools, standing approval summaries and `pinRequired` (`settings.controller.ts:111`). Helper preferences and native preferences have separate endpoints, so they are absent from this overview.

`GET /api/settings/public` requires no PIN. It contains only `publicUrl`, resolved sidebar, public enabled widgets, maximum pages, quick actions and enabled skill examples. Widget data-source addresses and skill secret headers are excluded (`public-config.service.ts:18`). Helper preferences, hotkey reads and helper size are also explicitly public routes. Other settings reads require the configured PIN; writes additionally require `x-nova-admin: 1`. PIN comparison is timing-safe (`settings.guard.ts:36`). Preserve these boundaries during route/UI moves.

Settings updates write `settings_change` audit entries (`settings.controller.ts:93`). User-created tools still pass normal action gating/confirmation. General status/memory APIs belong to their existing controllers, not to SettingsGuard: `apps/api/src/memory/memory.controller.ts:40`; memory creation/deletion use existing confirmable tool execution.

## Export/import boundaries

Current `nova-settings` format version 1 contains `exportedAt`, `persona`, nullable `quickActions`, `toolOverrides`, sanitized `skills`, `widgets`, nullable `sidebar` (`packages/contracts/src/settings.ts:315`; `settings.controller.ts:709`).

- Excluded: standing approvals and private hashes, helper preferences, helper mode/display, native hotkeys/views/wallpaper state, service/environment credentials, admin PIN, browser-local switches/volume, conversation history, memories and audit logs. This export is not a full deployment backup.
- Secret webhook header values are excluded; names are exported so the importer can return `missingSecrets`. Import strips incoming secret values and does not manufacture grants (`settings.controller.ts:738`).
- Merge keeps existing entries by ID and overlays incoming entries; replace clears the imported skill/widget/override collections before rebuilding. Persona/quick actions/sidebar are only changed where handled as present. The phase A import did not restore explicit null defaults; phase J fixes this (see transition below).
- Stable skill IDs, widget IDs, descriptions, parameter schemas, sidebar ordering and user-created panels must survive the UI redesign. Use the existing API/store before introducing migration schemas. Existing regression coverage: `apps/api/test/settings/settings-api.test.ts:222` (secrets), line 422 (backup), and helper/approval tests in the same suite.

## Management gaps relevant to phase J

There is no current settings page/deep-link/search/wizard, in-app service credential editor, model/provider connection editor, MCP connection editor, or Node-RED administration UI. Diagnostics and external admin links are not equivalent to NOVA managing configuration. The environment/service inventory records exact ownership and restart requirements. Any phase J credential changes need secret-safe persistence, explicit validation/testing, appropriate guarded APIs and honest applied/restart-required feedback. Free-only OmniRoute routing and existing confirmation/audit guarantees remain acceptance conditions.

## Phase J transition (2026-10-10)

- `/settings?section=<id>` now has twelve sections, navigation and shared search metadata. Legacy menu/dialog entry points redirect to it.
- Existing editors and APIs remain in use; the storage schema is unchanged. Embedded admin reports retain memory confirmations and existing modal behavior.
- Overview creates a private `settings.json.before-settings-page-v1` snapshot at 0600 before the transition. It is local, idempotent and never exported.
- Backup import now restores defaults for explicit `quickActions:null` and `sidebar:null`; omitted fields preserve their current values.
- Browser PINs now live only in memory, expire after fifteen minutes and can be explicitly locked; legacy localStorage PINs are removed.
- Five incorrect nonempty PIN attempts block that client for five minutes. Missing PIN reads do not consume attempts. Public route boundaries remain unchanged.

Service connection editors and bounded read-only checks are now available for nine services;
see the service inventory's update for endpoint ownership and remaining gaps. Service credentials
are absent from this overview and its backup; their presence flags are served separately behind the PIN guard.
